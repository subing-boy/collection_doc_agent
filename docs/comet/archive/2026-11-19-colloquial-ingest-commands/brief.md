# 目标

在交互终端 (`main.py`) 中实现基于“文件实体探测 + 本地零开销意图分流”的智能输入路由：
1. 无论用户输入是纯路径、中文指令紧挨路径（无空格）、还是口语化修饰长句，系统均能通过纯本地毫秒级正则从混合文本中精准抽取文件路径并完成磁盘实体校验（含 Windows 盘符映射与扩展名自动补全）；
2. 根据句子是否携带即时分析/疑问意图进行纯本地 0 Token 消耗的分流（纯存文档 vs 边存边答）；
3. 彻底避免关键词硬匹配与普通问答误拦截，保证极致响应速度与零无谓 API 开销。

# 范围

## 目录结构

### 修改
- `main.py`: 实现内嵌路径正则提取器（`extract_file_path_from_text`）、纯本地意图判别器与交互循环路由升级。
- `tests/test_skeleton.py`: 增加口语化紧挨输入、修饰短语及提问防误杀的自动化测试用例。

### 明确不建
- 不修改底层的 `AgentCore`、`parsers` 或 `storage` 核心接口。

# 非目标

- 第一、第二层意图分流严禁发起额外的 LLM 网络请求，确保路由判断在 1 毫秒内完成。
- 不影响现有的 `make-doc`、`make-ppt`、`list`、`exit` 等控制指令行为。

# 验收示例

- 输入 `存下来D:\协议文档\AIW Scenario Protocol Definition(11.3)` 时，能精准剥离动词，将路径归一化并补齐 `.docx` 后触发文档入库，绝不落入问答流。
- 输入带修饰前缀的 `帮我归档 D:\协议文档\AIW Scenario Protocol Definition(11.3).docx` 或 `存入: D:\协议文档\...`，能正确识别意图并触发入库。
- 输入带“存下来/归档”等词但无有效文件的提问（如 `为什么要存下来这个文档？` 或 `归档的标准流程是什么？`），必须准确识别为问答（`handle_ask`），严禁误报“文件不存在”。
- 原有 5 项全链路测试继续 100% 通过，沙箱自动销毁无残留。
