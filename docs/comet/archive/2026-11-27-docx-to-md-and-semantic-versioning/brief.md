# 目标

构建知识库两项深度进化特性：Word 文档统一按 Markdown 纯文本轻量化存储，以及基于“标题主干 + 语义相似度”的双因子版本归纳就地更新机制：
1. **Word 文档统一按 Markdown 轻量化落地存储 (`.docx -> .md`)**：
   - 当用户存入 Word (`.docx`) 文档时，系统不仅进行结构化切片，还自动将其转录为保留多级标题面包屑与 Markdown 表格的纯净结构化 `.md` 实体文件，物理保存在 `data/storage/<分类>/` 目录下；
   - 彻底告别动辄数兆字节的专有二进制 Office 封装体积，大幅降低存储开销并实现纯文本统一流转；
2. **双因子语义版本演进与就地归纳更新 (Two-Factor Semantic Versioning)**：
   - 在版本判定引擎中引入【标题主干归一化 + 文档级指纹向量余弦相似度】双因子机制：
     - **因子 1（主干提取）**：自动剥离文件名末尾的中英文版本号与日期标记（如 `(11.3)`, `（2.1.3，11.26）`, `_v1.0` 等）及不同后缀，提取纯净业务主干名称；
     - **因子 2（语义相似度）**：结合主干与全文摘要计算文档级指纹向量，与库内同主干文档进行语义余弦比对；
   - 当满足【主干一致且相似度 $\ge 0.85$】时，跨格式/跨日期版本自动识别为该文档的迭代升级，触发“象限 2：就地版本更新”，级联清除旧切片，无缝更新至最新切片与最新 `.md` 文件；
3. **安全脱敏与合规红线**：
   - 严格遵守 `GEMINI.md` 红线，全套测试用例与说明全量采用中立通用虚拟名称。

# 范围

## 目录结构

### 修改
- `parsers/docx_parser.py`: 提供从 Word 段落与表格结构无损导出 Markdown 全文字符串的工具方法。
- `core/agent_core.py`:
  - 在 `ingest_document` 中，当输入文件为 `.docx` 时，物理存储落地自动收敛为同名 `.md` 实体文件；
  - 实现标题主干归一化提取器与文档向量语义相似度比对逻辑；
  - 判定跨文件名/跨格式同源版本并触发级联清理就地更新。
- `tests/test_skeleton.py`: 新增针对 `.docx` 自动转 `.md` 存储与异名同源版本跨格式自动覆盖升级的端到端自动化测试用例。

### 明确不建
- 不引入 pandoc 等外部重型系统工具，完全基于纯 Python 原生内存数据流转换。

# 非目标

- 不改变 PPT、Excel、邮件等其他格式已有的正常解析与入库逻辑。

# 验收示例

- 用户存入 `.docx` 文档时，存储区物理生成的文件为带有结构化 `#` 标题与表格的 `.md` 文本文件。
- 先后存入带不同版本尾缀的同源规范（如 `协议规范(1.0).docx` 与 `协议规范（2.0，11.26）.md`），系统自动触发语义版本归纳更新，旧切片自动清除，切片总数不冗余翻倍。
- 全套端到端自动化测试套件继续 100% 通过，沙箱自动销毁无残留。
