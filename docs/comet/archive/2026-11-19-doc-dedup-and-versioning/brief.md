# 目标

在知识库入库链路中构建基于“文件内容 SHA256 哈希 + 原始文件名”的四象限防重复入库与版本就地迭代机制：
1. 场景1（同名且同哈希）：秒级拦截完全重复提交，提示已入库，跳过二次解析与向量化；
2. 场景2（同名但哈希改变）：就地版本迭代，自动级联清除该文档在 SQLite 与内存向量索引中的旧切片，无缝替换为新版本切片与物理文件；
3. 场景3（改名但哈希相同）：识别为文件副本/改名，建立别名映射（Alias），避免向量空间被 100% 重复切片污染；
4. 场景4（全新文件名与全新哈希）：按标准流程正常新建入库。

# 范围

## 目录结构

### 修改
- `storage/metadata_db.py`: 新增按 Hash/按文件名查询文档、更新文件名别名列表以及按 doc_id 级联删除旧切片的接口。
- `storage/vector_store.py`: 新增 `delete_doc_chunks(doc_id)` 接口，同步清除内存向量缓存中的失效切片。
- `core/agent_core.py`: 在 `ingest_document()` 中引入 SHA256 计算与四象限状态决策引擎，精确处理重复跳过、版本更新、别名绑定与新建入库。
- `main.py`: 适配四象限返回状态，展示人性化、差异化的高亮提示信息。
- `tests/test_skeleton.py`: 新增针对四象限场景的自动化测试用例。

### 明确不建
- 不修改底层的文档解析器（`parsers/`）和逆向生成器（`generators/`）。

# 非目标

- 不改变现有正常 RAG 问答与切片相似度计算流程。
- 不影响现有的 CLI 命令格式与参数。

# 验收示例

- 同名且同内容文件重复执行入库时，直接被秒级跳过，数据库切片总数不增加，且终端提示已跳过重复入库。
- 同名文件内容更新后重新入库，旧版本的旧切片被自动彻底清除，新切片就地替代，数据库中不残留该文档旧切片。
- 文件改名但内容一致重新入库时，不产生重复向量切片，且自动将新文件名追加为该文档的别名标签。
- 全新文件正常走全新入库流程；原有全链路回归测试继续 100% 通过，沙箱自动销毁无残留。
